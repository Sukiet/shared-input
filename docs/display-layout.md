# 显示屏布局与跨屏坐标

Windows 控制端在“屏幕边缘切换”下方提供“显示屏设置”。控制端为固定的紫色 1，Mac 为可拖动的灰色 2；松开后贴到控制端的左、右、上、下边缘，保留沿边偏移。

默认对角线尺寸为 Windows 17 英寸、Mac 14 英寸，Mac 在右侧且顶部对齐。尺寸可改为 5～100 英寸。宽高比由 Windows 主屏和连接时 Mac 返回的主屏尺寸计算，尚未取得的宽高比默认 16:10。断开后保留最近一次读取的比例。

## 坐标规则

- 由对角线和宽高比计算毫米宽高，拖动偏移也保存为毫米。
- 相邻方向的整条边均可切换，不将整条边按比例拉伸；位置超出目标屏幕范围时映射到最近端点。拖动吸附仍至少保留 10 mm 接边（非常小的尺寸按较小边的一半）。
- 从 Windows 到 Mac：`目标比例 = clamp((本地比例 × 本地沿边长度 - 偏移) / 目标沿边长度, 0, 1)`。
- Mac 回传实际指针位置后反向计算并限制到 `[0, 1]`，只要到达相邻边缘并满足向外移动意图，就可返回 Windows，无需当前位置处于两屏重叠区域。
- 接边映射独立于指针灵敏度、滚轮倍率。布局、尺寸、偏移和最近读取的比例写入现有设置存储。

## 实现入口

- `lib/display_layout.dart`：尺寸、拖动吸附、物理坐标和持久化模型。
- `lib/display_layout_dialog.dart`：配置弹窗。
- `windows/runner/screen_layout.h`、`input_bridge.cpp`：原生触边检测与返回坐标。
- `lib/remote/lan_session.dart`：握手返回主屏尺寸及 `edge-layout-v1` 能力，开始控制时传递入口方向。
- `macos/Runner/RemoteInputBridge.swift`：从指定屏幕边缘进入。

默认左侧入口仍兼容已有边缘切换协议，其他入口方向会检查新能力；旧版被控端会提示更新。

## 验证与待实测

验证覆盖四个方向的正反映射、大小不一致和正负错位时的端点映射、拖动保存、窗口较窄时布局、连接能力协商和旧版本兼容性。检查包括 Flutter 静态检查、Flutter 测试、原生测试和 Windows Debug 构建。

本机无法编译 macOS。Mac 端需同步本次改动，实测不同大小、错位排列及四个方向的进入和返回；两端屏幕分辨率或方向变化后需重新连接。当前仅配置各设备主屏。
