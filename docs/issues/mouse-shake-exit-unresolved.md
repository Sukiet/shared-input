# 后台控制时晃动鼠标无法退出（历史记录，功能已关闭）

- 当前状态：**2026-11-15 按用户要求关闭晃动退出，主线已移除检测逻辑及界面提示**。
- 原问题状态：**未解决，用户实机复测失败**；关闭功能不代表此前故障已修复。
- 记录日期：2026-11-14。
- 基线版本：`7e5569f`（Windows / Mac 后台边缘切换）。
- 尝试分支：`bugfix/shake-exit-unresolved`，仅保存调查和未成功的修复，不应作为修复完成的版本发布。

## 用户反馈

边缘切换实测正常，但后台控制 Mac 时，快速晃动鼠标退出疑似失效。改动检测算法后，用户再次反馈“并没有解决”。因此不能将当前改动认定为修复成功。

## 已尝试的改动

原检测从首次移动开始按固定 1.2 秒窗口清零。模拟输入可复现：先普通移动，再进行跨清零点的完整晃动，不能累计到足够的有效换向。

本分支尝试将检测改为基于最近换向的滑动统计，保留 600 raw counts 反向距离、6 次有效换向、4800 raw counts 总行程的门槛，并限制先前普通移动对行程统计的影响。

## 已执行的验证及其局限

- 原生单元测试覆盖先普通移动再晃动、不同起始时刻、小幅修正、慢速换向、多数据包、不同鼠标不合并计数等情况。
- Windows 桌面探针使用 SendInput 产生鼠标移动，经后台 Raw Input 和实际钩子链路验证，模拟晃动能够解除拦截。
- 上述测试通过，**但用户实际使用时仍无法通过晃动退出**。自动注入结果不能代替真实设备与两机联调验证，也不能证明已经定位了用户问题的根因。

## 后续调查方向

以下仅为待验证方向，不是已确认原因：

1. 用户触发时是否实际进入检测代码，以及停止原因是否已被其他返回路径覆盖。
2. 真实设备的相对 / 绝对坐标标记、设备句柄稳定性、原始位移、有效换向计数与行程是否达到门槛。
3. 后台控制、窗口内控制、不同鼠标报告率和 DPI 下的数据是否存在差异。
4. 边缘返回、鼠标钩子拦截与晃动检测的交互时序。

继续调查应采用可选、短期的聚合诊断，避免记录键盘内容或连接码；在真实使用场景复测成功前，保持“未解决”状态。用户要求暂停本问题的修复工作，先以基线版本开发滚轮速度调节。
