# Windows 发起拖拽时的跨屏状态机测试

基线 `7d3d297`（透明 1 像素、本地识别版，已提交）。本次在其上允许 Windows 文件拖拽触发鼠标控制跨屏，不实现文件传输或 Mac 原生文件拖放。

## 使用与观察

1. Mac 开启接收，Windows 设置好连接地址、连接码和退出快捷键，打开“屏幕边缘切换”。现有支持边缘切换的 Mac 版本即可，无需更新 Mac 代码。
2. 打开 Windows 的“边缘拖拽测试”。接收区域依然完全不可见，界面显示区域是否打开。
3. 按住左键或右键向所配置屏幕边缘推，显示“进入拖拽手势”和“屏幕边缘已接收”，可以直接跨屏。OLE 文件识别仅用于展示，不决定跨屏；即使还没有文件列表，按住移动也可跨屏。
4. 自动连接并请求 Mac 开始接收，通过原生校验后显示“已跨机器 · Mac”。界面保留完整状态路径和文件列表。
5. 在 Mac 一侧松开起始按钮，显示“退出拖拽手势 · Mac”；鼠标继续控制 Mac。或者保持起始按钮按住，从 Mac 返回边缘或按退出快捷键，显示“回到原来的机器 · Windows”，本次跨机流程结束，清除进行中的手势标志。源按钮仍按物理状态归属 Windows，松开后可以重新开始新的拖动。

状态路径：进入拖拽手势 → 屏幕边缘已接收 → 正在跨屏 → 已跨机器 → 退出拖拽手势 / 回到原来的机器。先松手再返回时两者分别记录；先返回时流程即结束，迟到的松手不改变终态。文件识别阶段和鼠标所在机器分开显示。

这是 Windows 发起的单向实验；不识别 Mac 发起的源对象。测试开关开启时，普通开始按钮和无拖拽的边缘进入保持可用；没有按键按住时走常规跨屏，按住鼠标时走测试跨屏。保持同一次按住从 Mac 返回后，再向 Windows 边缘推即可再次跨过去，无需松手或产生新的 DragEnter。

## 实测反馈后的修正

首个测试版的用户反馈：开启测试后普通鼠标无法跨屏；拖拽返回后仍显示进行中的拖拽，不能继续跨屏。

已移除 Dart 开始条件、原生 Start 和普通边缘检测里对测试开关的排斥。Returned 现在同时结束跨机流程的手势，清除源按钮标志，不再等待可能迟到的释放消息。是否保持原位以保护源文件，在清除流程前独立判断，不以终态反推物理按键。

原始鼠标释放包独立补齐手势结束，放在控制状态、前台状态判断之前，返回 Windows 后也会处理。既有钩子线程的 50 ms 消息泵在观察到按住的源按钮期间校正释放状态；GetAsyncKeyState 只在钩子回调之外查询，只清除已释放按钮，不凭采样制造按下或新手势，不增加定时器。通知投递失败时不会提前标记成功，后续泵可重试。

随后实测确认，持续按住返回后仍不能再次跨屏。此前只修正了终态及新的按下流程，遗漏同一次按住没有第二次按下、也可能没有第二次 OLE DragEnter 的路径。本次改为原始鼠标向外推边缘驱动每次测试跨屏，返回后下一次推边缘创建新流程编号；按住测试路径不依赖文件识别结果，不使用普通跨屏的 500 ms 返回等待和 1 秒重复请求间隔。每个正在建立的连接仍只发起一次请求；失败后再次向外推可以重试。Dart 忙碌或尚未处理上一轮停止时到达的新流程，在停止或忙碌结束后继续处理。

## 输入归属与取消

- 起始按下发生在 Windows，因此该按钮一直归 Windows。仅放行这一个左键或右键；额外鼠标按钮或任何键盘键按住时仍拒绝开始。普通控制原有的全部松开检查不变。
- Mac 只接收之后的指针移动，不补发源按钮按下，也不接收它的孤立松开。Windows 通过原始松开结束本地拖放；之后在 Mac 的新点击按正常远控处理。
- 回程仅忽略这一个 Windows 所有的起始按钮。真正发给 Mac 的按钮或键盘仍按原规则阻止边缘返回。快捷键和既有保护保留。
- 开始前、网络连接后、Mac 确认后和原生接管时重新检查源按钮、流程编号和边缘位置。连接期间松手或离开边缘会取消；原生失败则结束 Mac 接收，保留网络连接。再次推边缘即可重试，无需松手。
- 流程编号递增，清空和开关重置也使旧编号失效，迟到的网络结果不能开启新控制。Mac 内的新拖动不会替换当前 Windows 源流程。
- 所有 OLE 回调继续返回 `DROPEFFECT_NONE`。松手时若源 OLE 仍停留在接收窗口，保留拒绝放置区域，等 DragLeave/Drop 确认结束后再恢复穿透，避免先移除目标导致文件落到下方应用。
- 源拖拽尚未结束时，返回不把 Windows 指针挪进资源管理器，避免在真实目录中意外放置。源手势和 OLE 会话均结束后，返回仍使用原有屏幕位置映射。
- 拖拽进行中禁用测试开关和清空；来源窗口、文件及数据对象均不写入，不读取文件内容，不发文件网络数据。

## 验证

本次静态分析通过，88 项 Flutter 测试、13 项 Windows 原生测试全部通过。原生新增不松手、不发第二次按下、不等待 OLE 回调的连续五次往返，以及失败后仍按住重试；Flutter 回环增加没有识别到文件也可跨屏。真实 Mac 操作仍待用户复测。

Windows Debug 已构建并启动。自动测试没有代替实际 Windows → Mac 文件拖拽操作，需用户实测：跨过去后松手、按住返回、快捷键返回，再次拖动重试；确认状态路径、源文件未变、Mac 没有额外点击或按键卡住。
