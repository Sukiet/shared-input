# Mac 退出控制后的指针隐藏与归位

基线：`feature-drag-objects` 的 `bd4788c`。

## 已确认的问题

- 当前分支未包含本地 `14810cb` 的归位开关、持久化字段和原生执行逻辑。该提交保留在本地 master；切换到拖拽分支后，归位功能实际缺失。
- 原生接收超时调用默认的显示清理路径，与正常结束控制的隐藏行为不一致。
- 原先恢复显示只排除事件的自定义标记。标记丢失、本应用合成的未标记事件或排队的旧本机事件都可能被识别为本机接管，进而阻止之后隐藏。此处为代码风险，尚未证实为用户每次现象的原因。
- 提前隐藏首次失败后，`anticipating` 标记阻止后续重试。

## 修改

恢复独立可见的“控制结束后移至左上角”开关，默认关闭，保存并在启动时应用。目标为指针所在显示器的左上角，查询失败回退主屏。保留当前分支的拖拽识别、音频和锁屏清理。

恢复显示时检查事件标记、来源进程、来源状态以及发生时间。隐藏前发生的旧事件不能取消当前隐藏；隐藏后真实本机输入仍恢复显示，并阻止迟到的结束通知归位或再次隐藏。新的控制会话重置本机接管状态。

正常结束、原生接收超时和无效输入导致的停止统一执行隐藏及可选归位。初始化、重新进入、退出应用及系统锁屏清理继续显示指针，不额外归位。

归位在释放按键、按钮和停止运动计时器后执行；最后追加带本应用标记的定位事件，使此前排队的注入不再成为最终位置。提前隐藏在指针反馈时也使用反馈给 Windows 的相同坐标；预测状态不通过这条反馈捷径触发隐藏。原生计时器保留真实点和渲染点的双重边缘检查。

## 验证范围

原生回归检查覆盖四边、多个显示器的左上角坐标、注入标记、同进程未标记事件、过期本机事件、真实新本机事件、迟到的停止、失败重试和隐藏计数平衡。Flutter 验证开关显示、即时应用、持久化及与现有功能的集成。

这些检查验证代码逻辑，不能代替桌面/最大化窗口下的真实系统指针效果。双机实际隐藏时延、排队注入后的最终位置，以及 Mac 触控板/鼠标恢复仍需新版运行验证；不以系统接口返回成功代替肉眼效果确认。

本机结果：原生指针回归检查通过；固定开发证书 Debug 构建及签名校验通过。Flutter 全量测试 102 项通过、3 项失败，失败项为 Windows 显示器布局和键盘例外界面的 `identical(childRenderObject, parentRenderObject)` 语义断言。新归位开关及 Mac 相关测试通过，未在本次修改中处理这些 Windows 界面断言。
