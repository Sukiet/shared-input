# Windows 本机按键例外

基线：a2dfc09。新增允许在后台控制 Mac 时仍交给 Windows 处理的单键例外。

## 使用方式

控制端音频设置下方、断联日志上方增加“留在 Windows 的按键”。停止控制后点“添加例外”，在前台识别窗口按一个键，或向一个方向转动音量旋钮。识别成功后自动添加；重复键不增加条目；条目可逐项移除。例外保存在原有设置存储，重启时应用到原生钩子。

音量旋钮的增加、降低和按下静音分别属于不同的键，需要分别添加。常见结果为 VK 0xAF、0xAE、0xAD；悬停条目可查看识别出的虚拟键码。实际设备结果需要实体输入确认。

本版按 Windows 虚拟键匹配，所有键盘通用，只作用于后台边缘控制模式。它不按 USB 设备区分，也不识别整组快捷键。把 Ctrl 等修饰键添加为例外，会使该修饰键留在 Windows，不能把它与其他仍转发的键自动组合成 Windows 快捷键。退出快捷键优先于例外分流。

## 实现

- 低级键盘钩子对新按下事件选择 Windows / 远端归属，并将归属保持到重复及松开；本机例外调用后续钩子链，不排入远程输入消息，因此 Windows 可正常处理且 Mac 不收到该键。
- 控制结束后的远端按键松开仍由原钩子吞掉，避免给 Windows 发送孤立松开；同理，本机按键按下后的松开保持本机归属。配置仅允许在停止控制后修改。
- 识别使用同一原生低级钩子，不依赖 Raw Input 是否把旋钮作为普通键盘报告。仅在显式点击后、主窗口处于前台、10 秒期限内采集一个新的键按下；识别用的按下、重复与松开均消费掉，不触发所选键的本机动作。
- 取消、窗口失焦和超时停止识别。每次识别携带代数，取消后的旧原生结果不会用于下一次识别。界面禁止识别过程中开始控制。
- 钩子不执行 Dart、网络、文件或设备查询；只查询前台状态（识别时）、维护固定数组并投递原生窗口消息。原有鼠标钩子、看门狗和退出保护保持原来的职责。
- 若设备仅提供未转换为键盘事件的厂商 HID / 其他 Consumer Control 报告，此识别窗口可能收不到它；本版未新增独立原始 HID 解析。

## 验证

静态分析无问题，81 项 Flutter 测试与 11 项原生测试通过，Windows Debug 已构建并启动。自动测试覆盖单键持久化、非法数据和重复条目、识别媒体键、取消及过期结果、原生设置失败时保留配置、移除和重启恢复；原生路由测试覆盖例外键、普通键、重复、按住过程中规则改变、控制结束后松开与退出键优先级。

用户已在实体键盘上确认旋钮两个方向都能识别。后台控制期间的 Windows 音量响应及两端按键组合仍需实际使用确认。

验收：分别添加音量增加和降低，开启边缘控制并切到 Mac；转动旋钮应只调 Windows 音量，普通文字仍到 Mac，退出快捷键和边缘切回正常。按住普通键再退出、按住例外键再退出，确认两端都不卡键。移除例外后应恢复正常后台转发行为。仅需更新 Windows 端。
