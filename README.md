# Shared Input

局域网键盘鼠标共享。Windows 控制端通过 Raw Input 采集选中的设备；macOS 被控端通过 Quartz 注入键盘、鼠标、拖拽和滚轮事件。Windows 也提供被控端实现。界面顶部通过“控制端 / 被控端”切换角色。

## 连接两台电脑

1. 在 Mac 上构建运行同一项目：`flutter pub get`，然后 `flutter run -d macos`。需要 Xcode 和 Flutter 的 macOS 桌面工具链。
2. Mac 首次启动默认选择“被控端”。点击“辅助功能授权”，在系统设置 → 隐私与安全性 → 辅助功能中允许此应用；系统询问局域网访问时允许。点击“开始接收”，记下本机 IP、端口和连接码。
3. Windows 选择“控制端”，输入 Mac 的局域网 IPv4 地址、相同端口和连接码，点击“连接”。默认端口为 **45831**，TCP 和 UDP 使用同一个端口号。系统防火墙需允许本应用在使用的局域网中通信。
4. 选择目标键盘、鼠标，设置退出快捷键，调整灵敏度和发送频率，再点击“开始控制”。仅连接不会接管输入。
5. 退出快捷键、快速晃动鼠标、切走 Windows 窗口均可停止控制。Mac 可以在后台接收；“停止接收”或关闭应用会断开并释放远程按键。

尚未连接时，Windows 的“开始本地预览”保留原来的模拟功能，最多运行 30 秒；真正的远程控制没有 30 秒上限，使用心跳和断线保护。Mac 控制端采集尚未实现，当前主要方向是 Windows → Mac。

## 传输与持久化

- **鼠标移动：UDP。** 默认发送上限 **500 Hz**，可选 125 / 250 / 500 / 1000 Hz。Windows 原生多媒体定时器合并原始设备报告，通过平台通道直接交给网络层，不受 Flutter 预览帧率限制。每次最多一个待处理的原生发送通知。
- **键盘、按钮、滚轮、会话及心跳：TCP，开启 TCP_NODELAY。** 每个可靠事件携带当时的累计鼠标位置和事件编号；后续 UDP 必须等对应可靠事件执行后才能移动，保证点击 / 拖拽位置顺序。
- **剪贴板：独立加密 TCP 通道。** 连接后双向同步纯文字和单张图片，无需开始控制；开关会保存，详细行为见下文。图片分块、哈希和加密在单独的 Dart isolate 执行，Windows 图片编解码使用原生工作线程，Mac 使用后台 ImageIO 队列。
- UDP 使用累计位移、序号和随机控制会话 ID，跳过过期 / 重复数据。丢失中间包时，下一包补齐位移；TCP 心跳还携带最后的位置，补齐鼠标停止时丢失的末包。网络和注入繁忙时合并最新鼠标状态，不积压过期鼠标轨迹。
- **连接码认证并加密全部输入。** 随机 128 位连接码、双向随机握手、HKDF 派生不同方向 / 通道的密钥，ChaCha20-Poly1305 保护 TCP 和 UDP，拒绝被篡改及重放的数据。无需中转服务器。
- 通过系统偏好存储保存角色、目标 IP、端口、双方连接码、键鼠设备路径、退出键、灵敏度、细调步长、发送频率及统计面板展开状态。重启恢复设置；设备暂时拔出时保留其选择，不自动替换成其他设备。连接状态和正在控制的状态不保存、不自动恢复。
- 修饰键固定按物理键映射：**Win → Mac Command，Ctrl → Mac Control，Alt → Mac Option**，保留左右键区别。旧版保存的 Ctrl → Command 配置会被忽略，不再提供交换开关。
- 开始控制 / 本地预览时，为键盘 Raw Input 临时启用 `RIDEV_NOHOTKEYS`，抑制本机开始菜单和 Win 快捷键抢占焦点；左右 Win 始终规范化为扩展扫描码 E0-5B / E0-5C，继续按选定设备过滤后转发。停止、失焦、启动失败和看门狗退出均恢复普通注册。不需要全局键盘钩子或驱动。
- 专用原生采集子窗口解除本地 IME 上下文关联，并屏蔽组合输入 / 候选框 UI；每次开始和切换输入语言时重新检查。Windows 处于中文输入法时仍转发原始按键，目标 Mac 使用自身的输入法。Flutter 设置输入框和其他应用保留各自的输入法上下文及输入语言。
- 界面显示实际 UDP 包率和往返延迟。发送频率是合并 / 发送上限，实际包率受鼠标报告率、移动情况、系统调度和网络状况影响。

macOS 采用普通桌面应用方式运行，关闭 App Sandbox 以使用辅助功能事件注入；连接会话和加密在 Dart 中完成。Windows 接收端通过 SendInput 注入普通桌面事件，受 Windows 对目标进程权限的限制。

**验证范围：**Windows 构建和原生安全策略、真实 TCP/UDP 回环连接、协议加密 / 分帧 / 乱序修复、点击顺序、断线释放及持久化自动测试在 Windows 上执行。此前基础版本的 macOS Release 已使用 Flutter 3.47.6 和 Xcode 27.2 构建，通过静态分析和全部 28 项 Flutter 测试，并确认应用启动默认显示被控端。构建产物包含 arm64 / x86_64，最低系统为 macOS 12。Mac 辅助功能授权、键盘布局、拖拽和多显示器行为仍需按下方清单双机联调。

## 剪贴板同步

两端更新后，在连接区域开启“剪贴板同步”（默认开启）。连接期间双向自动同步，任一端关闭开关或断开连接都会停止同步；键鼠控制可以继续使用。首次建立同步时由 Windows 控制端同步当前剪贴板，之后两端新复制的内容均可同步。

- 文字支持中文、换行、Emoji，按 UTF-8 传输；Windows 写回 Unicode 文本并转换为 CRLF 换行。单次文字上限 1 MiB。
- 图片支持截图、网页“复制图片”等单张图片内容，统一无损转换为 PNG。Windows 读取 PNG / 系统位图，写回 PNG 和 DIBV5；Mac 读取 PNG / TIFF，写回 PNG。PNG 传输大小上限 32 MiB，解码尺寸上限约 3355 万像素，保留透明度。
- 当前同步纯文字或图片内容，暂不传输资源管理器 / Finder 中复制的文件，也不保留 HTML、RTF 或文字图片混排格式；不支持的内容不会清空对端剪贴板。超过大小限制的内容不传输。
- 图片使用临时协商的第二个 TCP 端口，无需手动配置；防火墙应允许本应用的局域网通信。每次最多排队一个 32 KiB 数据块并让出发送时间，新的复制会取消过时的传输。原有键鼠 TCP / UDP 通道不变。
- 同步使用版本号和来源标记防止循环回传，写入前检查本机剪贴板版本，避免用户在传输中复制的新内容被旧图片覆盖。剪贴板内容只保存在内存中，开关设置会持久化。
- Mac 如果出现读取授权提示，应在系统设置中允许 Shared Input 访问剪贴板；授权后重新开启同步。剪贴板失败或权限不足只影响同步，连接和键鼠控制继续工作。

实现及验证记录见 [剪贴板同步](docs/clipboard-sync.md)。本次 Mac 原生代码和新增的 ImageIO 单元测试尚未在本机编译执行，需在 Mac 上更新、构建并做双机验证。

## macOS 被控端构建

需要 Flutter、Xcode 和 macOS 12 或以上。

```sh
flutter pub get
flutter build macos --release
open build/macos/Build/Products/Release/shared_input.app
```

首次使用请点击“辅助功能授权”，在系统设置 → 隐私与安全性 → 辅助功能中允许应用，然后返回点击“开始接收”。Windows 控制端填写 Mac 的可达 IP、端口（默认 45831）和界面中的连接码。

### 鼠标平滑设置

Mac 被控端顶部可即时调整插值开关、平滑时长（1–100 ms，默认 12）、更新间隔（1–16 ms，默认 4）和调度容差（0–2 ms，默认 0.5）。支持恢复默认，所有参数自动保存，重启恢复。控制中修改不需要重新连接；关闭插值后立即到达最新目标并直接跟随后续位移。平滑时长越大，跟手延迟越大；更新间隔和容差越小，定时唤醒开销通常越高。定时更新受系统调度影响。

macOS 被控端默认使用 12 毫秒线性插值，由独立原生定时器每 4 毫秒更新一次指针。新位移从当前插值位置转向最新目标，不排队播放旧轨迹，也不进行惯性外推；最后一包后约 12 毫秒到达目标并停止。键盘、按钮和滚轮事件先立即到达其对应位置，再执行状态变化，保证点击和拖拽顺序。停止接收、断开或看门狗超时时丢弃剩余插值。会话开始时读取系统光标，此后按远端累计位移维护目标，避免将尚未落地的注入误判成本机移动而回拉指针。长时间收包空窗仍可能表现为停顿。

### 预测补偿模式

Mac 被控端的“鼠标处理模式”可选择直接跟随、平滑插值或预测补偿，三者互斥。预测模式下空窗超过阈值后按近期速度进行指数衰减外推，真实累计位置始终独立保存。可在预测内部启用“预测输出平滑”（默认开启，时长默认 8 ms、范围 1–40 ms），对正常移动、外推点和真实数据恢复后的纠偏做短时线性追赶；关闭后恢复原来的直接输出。此开关独立于“平滑插值”模式，开启会增加跟随延迟。默认触发 8 ms、预测上限 60 ms、衰减时间 40 ms、估速窗口 20 ms、位移上限 32 个光标坐标单位；界面中均可调整，更新间隔与调度容差也可调整，设置即时生效并持久保存。

预测可能在突然停手、转向时过冲或回跳。点击、按键、滚轮事件先回到真实位置并清除预测；鼠标按钮按住期间直接跟随；模式切换、停止、断线和看门狗结束时清空历史。预测坐标的指针反馈使用无效序号，不触发自动跨屏切回。

**Windows 控制端也必须使用本次源码重新构建。** 新端通过 `motion-prediction-v1` 协商 64 字节鼠标帧（加密后 92 字节），携带原生单调时间戳和运动/静止标记；停手后原生定时器约每 16 ms 发送状态，按累计位移不重复注入运动。旧端继续使用 48 字节帧，缺少时间戳时 Mac 的预测模式退化为直接跟随。估速使用发送端时间差，网络攒包不会被当成超高速移动；预测位移始终独立于真实累计位移。当前静止判定仍可能被发送线程调度或网络延迟影响，预测时间与距离上限限制这种情况下的漂移。

本机算法检查可运行：

```sh
mkdir -p build/native
xcrun swiftc macos/Runner/PointerInterpolator.swift macos/Runner/PointerPredictor.swift test/native/mac_pointer_predictor_test.swift -o build/native/mac_pointer_predictor_test
build/native/mac_pointer_predictor_test
```

### 鼠标卡顿诊断

使用 `flutter build macos --release --dart-define=INPUT_DIAGNOSTICS=true` 构建诊断版，重新启动应用并连接控制端。每次连接的汇总日志写入 `~/Library/Logs/SharedInput/diagnostics-*.jsonl`；普通构建默认不启用诊断。

日志每秒记录 UDP 收包间隔、计数器缺口、解密耗时、待处理位移合并、等待可靠事件的次数、平台通道往返，以及原生锁等待、显示器查询和事件提交耗时。不记录连接码、按键内容或光标坐标。耗时单位为微秒。

收包空窗包含用户停手；UDP 计数器缺口包含乱序，不能直接作为丢包率。100 毫秒周期的 Dart 定时器只提供粗粒度调度观测，不能排除周期之间的短暂停顿。原生事件提交耗时不代表事件已经显示在屏幕上。需结合连续移动样本、独立网络探测和控制端发送计时定位问题。

## 运行

需要 Flutter、Visual Studio 的“使用 C++ 的桌面开发”和 Windows SDK。

```powershell
flutter pub get

```

也可执行 `flutter build windows --debug`，然后打开 `build\windows\x64\runner\Debug\shared_input.exe`。分发时需要保留该目录内的 DLL 和 data，不能只复制 exe。

## 使用流程

已知问题：后台控制时的晃动退出在用户实机上仍未解决，当前不要依赖它作为唯一退出方式；请保留已设置的退出快捷键。记录和未成功的修复尝试见 [问题文档](docs/issues/mouse-shake-exit-unresolved.md)，尝试代码单独保存在 `bugfix/shake-exit-unresolved`，未并入此版本。

Windows 控制端的“滚轮速度”独立调整 Mac 上的滚动倍率，支持 **0.01～20 倍**，默认 **3 倍**，可用滑杆或输入框按 0.01 精度调整，自动保存。横向与纵向滚轮均生效，不影响指针灵敏度和原滚动方向。Mac 端需同步更新以识别倍率；旧控制端连接新版 Mac 时保持原滚动行为。

### 后台边缘切换

在 Windows 控制端启用“屏幕边缘切换”，先设置退出快捷键并填写 Mac 地址和连接码。开关会保存，应用可最小化或留在后台；两端都需要更新到支持边缘切换的版本。

- 点击开关下方的“显示屏设置”，紫色 **1** 是固定的 Windows 控制端，灰色 **2** 是可拖动的 Mac。松开后 Mac 自动贴到控制端左、右、上、下的一侧，可沿接边错位排列；默认 Mac 在右侧、顶部对齐。
- 两端对角线尺寸默认 **17 英寸 / 14 英寸**，可修改并自动保存。宽高比从两端主屏读取，未获取时按 16:10 示意。位置按物理长度和排列偏移映射；相邻方向的整条边均可跨屏，超出另一块屏幕范围时落到最近的边界端点，不把整条边拉伸对齐。
- 将鼠标移到 **Windows 与 Mac 相邻的边缘并继续向外移动**，应用自动连接并开始控制 Mac。默认从 Windows 主屏右边缘进入 Mac 主屏左侧；进入位置按设置的大小和偏移换算。
- **Mac 指针到相邻边缘，并继续朝 Windows 移动**，Windows 根据 Mac 回传的实际坐标和输入序号决定切回；Windows 指针恢复到相应边缘内侧的对应位置，超出范围同样映射到最近端点。左右及上下排列均支持，新布局需要两端同步更新。
- 控制期间全部键盘、相对位移鼠标的输入一起切到 Mac；后台模式不使用设备选择。先松开所有按键和鼠标按钮，再跨屏；拖拽或按住修饰键时不会切回。
- **原有退出快捷键和快速晃动鼠标退出均保留**，退出后恢复 Windows 输入，保留网络连接以便下一次跨屏。断线、指针反馈超时或输入拦截异常也会恢复本机操作。
- 当前配置针对两台设备各自的主屏，不跨屏拖拽文件。仅提供绝对坐标的触控板不作为相对位移鼠标处理。后台拦截面向普通桌面，Windows 安全桌面 / Ctrl+Alt+Del 不属于接管范围。

Windows 后台键盘由原生 DLL 的低级钩子采集，鼠标使用后台 Raw Input 保留原始位移；原生独立线程执行钩子，回调不等待 Flutter 或网络。Mac 约每 16 ms 通过已认证加密连接反馈实际指针坐标，鼠标发送频率和灵敏度沿用现有设置。控制结束或退出应用会解除拦截；`shared_input_hooks.dll` 随 Windows 程序一起分发，不能单独删除。

### 窗口内控制 / 本地预览

1. 打开应用，在设备列表中选择键盘和鼠标。可点击“识别”，再按目标键盘或移动目标鼠标。设备接口路径可悬停查看。
2. 点击“设置退出快捷键”，实际按下退出键，例如 **Ctrl + Alt + F8**。支持 Ctrl + Alt + 字母键或 F6～F11，可加 Shift。Esc、10 秒超时或失焦取消录制，原先有效的配置仍保留。配置会持久化，重启后恢复到原生退出判断。
3. 松开所有键盘按键，点击“开始控制”；也可在控制端窗口按下并松开 **Space**，未连接时先按保存的 IP、端口和连接码连接，成功后开始控制，已连接时直接开始。需要先选好设备并设置退出键；编辑输入框、录制退出键、识别设备或正在控制时不会触发。长按不重复触发，连接失败不会转为本地预览，连接或启动过程中切走应用会取消本次自动开始。界面保留“快速晃动鼠标退出”的提示，无需额外勾选确认框。
4. 鼠标被隐藏并限制在窗口中心的一个像素内；所选鼠标移动右侧模拟指针。已连接时，键盘、按钮、滚轮和相对位移也发送到被控端；本地预览时只增加模拟计数。其他设备的普通事件被过滤。
5. 按已录制的退出键，或快速左右 / 上下往返晃动鼠标，检查退出原因和鼠标恢复。“输入统计”默认折叠，展开后可检查模拟按下状态清零。可以再次手动开始。

USB 标记来自设备的 USB 父级链路，**不等同于外接设备**。内置 USB 设备、无线接收器和多个 HID collection 都可能出现在列表中，请通过实际输入识别。设备路径用于本次选择，重插后应重新检查；不永久保存 hDevice。

## 退出保护

| 保护 | 行为 |
|---|---|
| 开始前的强制检查 | 原生层再次验证前台焦点、所选设备存在、退出键已设置、没有键盘按键按住 |
| 退出快捷键 | 在 Windows 原生层识别，先于设备过滤；普通键盘消息另有备用路径，任意键盘可触发，无需 Dart 返回 |
| 快速晃动鼠标 | 先于设备过滤，任意提供相对位移的鼠标均可触发；每台鼠标分别计算，1.2 秒内至少 6 次有效换向，每次反向距离至少 600 raw counts，总行程至少 4800 counts。检测使用原始位移，不随模拟指针灵敏度缩放 |
| 失焦 | 切换应用、捕获输入窗口失焦、最小化时退出，不自动恢复 |
| 设备拔出 | 所选键盘或鼠标移除时退出，不自动替换设备 |
| 窗口变化 | 移动、调整大小、DPI 改变、关闭时释放捕获 |
| 本地预览时限 | 原生独立看门狗在 30 秒时释放鼠标并通知退出；远程会话使用心跳保护 |
| Flutter 心跳 | Dart 每 500 ms 发心跳，中断 3 秒后独立看门狗释放鼠标 |
| 接收端看门狗 | Windows / Mac 原生线程独立检查；1.5 秒未收到有效输入或网络心跳时释放本会话注入的按键和按钮 |
| 网络断开 | TCP 断开立即清理，心跳超时约 1.8 秒关闭会话；控制端停止原生采集并释放鼠标 |
| 清理 | 先解除本应用持有的 ClipCursor，再清空模拟按键 / 按钮；延后恢复窗口焦点并通知界面 |

看门狗使用独立线程，每 50 ms 检查一次，即使 Flutter 或原生消息循环停顿也会解除鼠标限制；若消息循环停顿，界面退出提示将在循环恢复后显示。会话代数和互斥锁防止上一轮超时误伤下一轮捕获。

鼠标释放前检查限制区域是否仍属于本会话，避免取消其他应用新设置的限制。失焦回调内只停止采集和释放鼠标，窗口显示 / 焦点恢复延后到消息队列处理，避免焦点重入。

**窗口内模式边界：**没有全局切换快捷键、BlockInput 或驱动。控制期间使用前台 Raw Input 的快捷键抑制，普通输入由原生子窗口消费；Alt+Tab、Ctrl+Alt+Del 等系统保留操作仍交给 Windows，切走应用即退出。这不是系统级独占输入。触控板若只提供绝对坐标，不参与相对位移的晃动识别。晃动阈值按原始计数计算，实际手感随鼠标 DPI 改变，需要真机校准。

模拟指针灵敏度范围为 **0.0001～4 倍**，默认 **0.1000 倍**。可输入四位小数；加减步长默认为 **0.0001**，可选 0.001、0.01 或 0.1。滑块采用对数刻度，低倍率区间也有足够的调节空间。原生侧始终累加浮点位移，例如 10,000 次单计数位移在 0.0001 倍下累计移动 1 个模拟坐标单位，不会逐次取整丢失。此设置不改变本机鼠标速度。

指针显示不再依赖每 100 ms 一次的统计消息。Flutter 在每个显示帧通过 `pointer` 读取原生最新位置，同一时间最多一个请求，避免排队播放过期位置。位置通过 ValueNotifier 驱动 CustomPainter，只重绘指针，不触发整页重建，也不使用补间动画；统计数据仍以 10 Hz 单独刷新。模拟桌面按相同的 X/Y 比例显示，窗口变化不会拉伸鼠标运动方向。实际帧率取决于显示器刷新率和设备运行状况。

## 自动检查

Windows 可直接运行下列脚本，自动查找 Visual Studio 自带的 CMake：

```powershell
.\tool\check.ps1
# 如需同时构建 Windows 调试版：
.\tool\check.ps1 -BuildWindows
```

也可以分别运行（需要 CMake 在 PATH 中）：

```powershell
flutter analyze
flutter test
cmake -S test/native -B build/safety_tests
cmake --build build/safety_tests --config Debug
ctest --test-dir build/safety_tests -C Debug --output-on-failure
```

测试包括真实 localhost TCP/UDP 连接、加密认证失败、接收授权失败、事件顺序屏障和断线释放；协议测试覆盖 TCP 分片 / 合包、加密篡改 / 重放、累计位移修复；持久化测试覆盖所有字段、并发保存和重启恢复。Flutter 界面测试覆盖原生退出键恢复、设备重插、细调灵敏度、预览刷新和角色切换。C++ 测试继续验证低速位移与退出保护策略。

Windows 原生测试还验证左右 Win 扫描码、缺失扫描码回退和按下 / 松开的状态标识，以及真实窗口的 IME 上下文隔离、输入语言变化后的隔离和设置输入框上下文保留。`test/native/win_key_capture_probe.cpp` 是需显式运行的交互桌面探针，不加入无头 CTest：它短暂创建测试窗口，优先为自身 UI 线程启用已安装的中文布局，用 SendInput 检查左 Win、右 Win+R 和字母仍到达 Raw Input 且没有抢走焦点或产生 IME 组合输入，并验证工作线程恢复普通注册。构建后从仓库根目录运行 `build\safety_tests\Debug\win_key_capture_probe.exe`，结果写入 `build\win_key_capture_probe.txt`；物理 USB 键盘和 Mac Command 仍需两机联调。

## 真机验收清单

自动测试不能替代物理 USB 设备与 Windows 焦点交互验证。按以下顺序逐次试跑：

- 未设置退出键时，不能开始；录制无效组合键时，不能绕过门槛。
- 按目标 USB 键盘、移动目标鼠标有对应计数；内置键盘 / 触控板不影响模拟桌面。
- 按住一个普通键或鼠标按钮，再用退出键结束：展开统计查看按住数量归零，本机鼠标恢复。
- 输入 0.0001 或 0.0017，测试低速位移；使用加减按钮验证细调，再拖动滑块检查低倍率区间。
- 所选 USB 键盘和另一台键盘分别测试退出组合键。
- 控制期间分别测试左 / 右 Win 和 Win+C、Win+R 等组合：本机不打开开始菜单 / 对应工具，Mac 收到 Command；退出后验证本机 Win 键恢复正常。
- 明确地连续左右 / 上下大幅晃动约 3 个来回可退出（仍须满足换向、时间和行程阈值）；小幅快速修正、慢速往返、普通点击不退出。鼠标 DPI 不同，物理幅度会有差异。
- Alt+Tab、最小化、移动窗口、拔出所选设备分别退出，返回后不会自动开始。
- 未连接时，本地预览等待 30 秒自动退出；远程会话可持续运行，每次退出后都必须重新点击开始或在窗口按 Space。
- 两台电脑配对，验证 Mac 普通输入、中文输入法、组合键、点击 / 双击 / 拖拽、滚轮和多显示器；分别验证 Win → Command、Ctrl → Control、Alt → Option 以及左右修饰键。
- 拔掉网线 / 关闭被控端应用，验证两端解除控制并释放按键；断线后不会自动开始控制。
- 重启两端，验证角色、连接码、目标地址、设备、退出键、灵敏度与步长恢复，但连接和控制仍需手动开始。
- 用调试器只暂停 Dart isolate，验证约 3 秒后鼠标解除限制；不要暂停整个进程的所有线程来测试进程内看门狗。
